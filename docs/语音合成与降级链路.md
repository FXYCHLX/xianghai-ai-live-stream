# 语音合成与降级链路

数字人「会说话」这件事，在项目里拆成两层：**先要有人声，再要口型跟着动。**

## 一、人声从哪来：两级降级

```
前端 speak(text)
   │
   ├─① POST /api/tts  ──► 服务端 MsEdgeTTS（微软 Edge TTS，音色 zh-CN-YunxiNeural 云希男声）
   │       │ 成功：拿回 audio/mpeg，用 <audio> 播
   │       │ 失败 / 超时 / 未装依赖
   │       ▼
   └─② 浏览器原生 speechSynthesis（Web Speech API）
          断网也能出声，只是音色取决于用户设备装了哪些中文语音包
```

**为什么这么设计：** 演示现场最怕的不是「声音不好听」，是「没声音」。服务端 TTS 的音质明显更好，
但依赖网络和 npm 包；浏览器合成是系统自带的，零依赖、可离线。
所以优先级给服务端，兜底给浏览器——**任何一端挂了，直播都不该停。**

实现见：

- `server/tts.js` —— 服务端合成（`synthesize` + `handleTTS`）
- `src/views/Live.vue` —— 前端播放与降级（`speak()`，先 fetch `/api/tts`，catch 后回落 `speechSynthesis`）

## 二、口型怎么跟着动

不是音素级同步，是**双帧切换 + 按语速估算节奏**：

- 主播只有两张图：`host.png`（闭嘴）、`host-talk.png`（张口）
- 按朗读节奏随机切换：张嘴 130–280ms、闭嘴 80–210ms
- 观感自然，但做不到逐音素对齐——这是这套方案的上限，写在这里免得误读

## 三、踩过的坑（都是真踩的）

| 问题 | 现象 | 处理 |
|---|---|---|
| 两句话叠在一起 | 上一句没播完就点下一件商品 | 每次说话前先 `stopAudio()` 掐掉上一段 |
| 音色不像男声 | 浏览器合成挑到了女声包 | 在 `getVoices()` 里按名字优先匹配 Yunxi/Yunyang/Yunjian 等中文男声 |
| 服务端没装依赖 | `msedge-tts` 缺失导致接口 500 | 捕获异常后前端静默降级，不弹错、不白屏 |
| 文本过长 | 一次合成几百字，首字延迟明显 | 服务端截断到 600 字，只合成当前这一句 |

## 四、一句话总结

**语音这条链路的可靠性，不是靠选一个最好的引擎，是靠每一层都留了退路。**
